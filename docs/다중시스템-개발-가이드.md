# 한 저장소에 여러 시스템 — Codex 컨텍스트 구조

> 유치원 급식 저장소를 개발·운영하는 Codex 담당자를 위한 현재 가이드입니다.

## 0. 원칙

한 저장소에서 정산과 비교 시스템을 함께 운영하되, 매 작업에는 필요한 문서만 읽습니다.
지침·설계·세부 작업을 세 층으로 나누면 불필요한 컨텍스트와 문서 드리프트를 함께 줄일 수 있습니다.

```text
AGENTS.md                         매 세션 자동 로드 · 지도와 공통 규칙
docs/systems/<시스템>.md          해당 시스템 작업에서만 읽는 색인·산식
docs/systems/<시스템>/<작업>.md   필요한 작업 단위 문서 하나
docs/archive/implementation/      과거 조사·구현 기록, 필요할 때만 조회
```

Codex는 저장소 루트부터 현재 작업 디렉터리까지 `AGENTS.md`를 계층적으로 읽습니다.
루트 파일은 짧게 유지하고, 하위 디렉터리 전용 규칙이 생길 때만 그 위치에 별도 `AGENTS.md`를 둡니다.

## 1. 작업 시작 절차

1. 요청의 `[정산]` 또는 `[비교]` 헤더를 확인합니다.
2. 루트 `AGENTS.md`를 기준으로 해당 시스템 문서 하나만 엽니다.
3. 정산 문서가 안내하는 하위 문서가 있으면 작업에 필요한 파일 하나만 추가로 엽니다.
4. 공용 경계를 수정할 때만 양쪽 시스템 영향을 함께 검사합니다.
5. 과거 의사결정 근거가 필요할 때만 `docs/archive/implementation/`을 검색합니다.

헤더가 없고 대상 시스템을 코드나 경로로 확정할 수 없으면 사용자에게 확인합니다.

## 2. 문서 계층

### 1층 — `AGENTS.md`

- 시스템 지도, 모듈 경계, 안전 규칙, 공통 검증 명령만 둡니다.
- 구현 상세나 긴 조사 결과를 넣지 않습니다.
- 커밋·푸시·배포 권한 같은 운영 규칙은 다른 문서에 중복하지 않습니다.

### 2층 — `docs/systems/<시스템>.md`

- 시스템의 현재 상태, 불변식, 산식, 하위 문서 색인을 둡니다.
- 코드가 참조하는 섹션 번호는 다시 매기지 않습니다.
- 구현이 바뀌면 같은 작업에서 문서도 함께 갱신합니다.

### 3층 — `docs/systems/<시스템>/<작업>.md`

- 큰 시스템 문서를 작업 단위로 분리합니다.
- 마감, 수금, 청구처럼 서로 독립적인 영역을 섞지 않습니다.
- 상위 문서는 요약과 링크만 유지합니다.

## 3. 반드시 피할 함정

1. 루트 지침만 줄이고 실제로 읽는 하위 문서를 방치하지 않습니다.
2. 새 내용을 문서 끝에 누적하지 말고 기존 절과 통합합니다.
3. 운영 중인 비교 시스템 문서가 구현보다 뒤처지지 않게 합니다.
4. UI 문구·클릭 수·경로 같은 검증 가능한 값은 코드와 대조합니다.
5. 코드가 참조하는 문서 섹션 번호를 분할 과정에서 바꾸지 않습니다.
6. 존재하지 않는 절을 코드 주석이 참조하지 않는지 검색합니다.
7. 테스트 파일에 일회성 `console.log` 스크립트를 두지 않습니다.
8. 오류 필터로 진짜 실패를 숨기지 않습니다.
9. 빌드 시각과 실제 배포 버전을 혼동하지 않습니다.

## 4. 검증

공용 코드 또는 문서 경계를 바꾼 뒤 다음 순서로 확인합니다.

```bash
npx vitest run src/lib
npx tsc --noEmit
npx next build
```

추가 점검:

```bash
# Codex 이전 전용 지침이 활성 경로에 남았는지 확인
rg -n -e 'CLAUDE[.]md' -e 'claude''docs/' AGENTS.md src docs/systems supabase

# 지나치게 큰 시스템 문서 찾기
find docs/systems -name '*.md' -print0 | xargs -0 wc -c | sort -n

# 문서 경로와 코드 참조 확인
rg -n 'docs/systems|docs §' src docs/systems
```

## 5. 현재 경계

- `src/features/settlement`와 `src/features/comparison`은 직접 import하지 않습니다.
- 공유 코드는 `src/features/shared` 또는 `src/lib`를 거칩니다.
- 비교 시스템은 운영 중이므로 공용 파일 변경 시 전체 검증을 수행합니다.
- 과거 구현 자료는 보관 기록이며, 충돌하면 `AGENTS.md`와 `docs/systems/`의 현재 문서를 우선합니다.
