## 15. 접근 권한 (2026-07-31)

```
퍼스트 컨설팅  /app
├─ 급식 정산 시스템                     [화이트리스트 전체]
│  ├─ 급식 정산      /app/settlement
│  ├─ 수금·지급      /app/settlement/collection
│  └─ 경영 보고서    /app/settlement/report
└─ 급식 단가 비교    /calc-food          [화이트리스트 + can_access_comparison]
```

**비교 시스템 URL은 옮기지 않았다.** 운영 중이라 북마크·공유 링크가 깨진다.

### ⚠️ 정책 변경 — `/calc-food`가 공개에서 제한으로 바뀌었다

2026-07-30까지 `/calc-food`는 **로그인 없이** 열려 있었다 (middleware matcher에
없었고 페이지 가드도 없었다). 거래처 단가가 담긴 데이터라 좁혔다.

두 조건을 **모두** 만족해야 한다:

| 층 | 무엇을 막나 |
|---|---|
| `middleware` — `/calc-food` | 미로그인 → `/login` (UX용 빠른 리다이렉트) |
| `middleware` — 비교 API | 미로그인 401 / 권한 없음 403. **`X-App-Secret`은 통과** (내부 배치 보호) |
| `/calc-food/layout.tsx` | `requireComparisonAccess()` — **실제 보안 경계** |
| 런처 3클릭 | **은폐일 뿐.** 권한 없으면 컴포넌트가 렌더되지 않는다 |

⚠️ **API 가드가 없으면 화면만 막힌다.** 로그인한 정산 담당자가 `/api/products/...`를
직접 호출해 단가를 볼 수 있다. 그래서 미들웨어에서 권한까지 본다
(화이트리스트 PK 조회 1회 — 지연을 감수한 이유).

⚠️ 이전에 이 저장소에는 **"비교 API는 세션 조회를 하지 않는다"는 회귀 방어 테스트**가
있었다. 정책이 바뀌었으므로 그 보장을 의도적으로 뒤집고 테스트를 새로 썼다
(`auth-middleware.test.ts`).

`can_access_comparison`은 **기본 false**다 (migration 056). 화이트리스트에 있다고
자동으로 열리지 않는다.

- 3개 화면이 각자 연월 선택기를 갖고 있다. 공통 선택기로 묶어야 한다.
- 런처에 "이번 달 어디까지 했나"(정산·계산서·수금·지급 진행률)를 띄우면 다음 할 일이

## 16. 시스템별 배포 버전 (2026-07-31 구현)

두 시스템은 **한 저장소에 있지만 배포 주기가 다르다.** 정산만 고쳐도 비교 시스템까지
같이 배포된다.

예전에는 비교 화면에 `NEXT_PUBLIC_BUILD_TIME`(빌드 시각)을 찍었다. 정산만 고친
배포에서도 이 값이 바뀌어, 비교 시스템 사용자에게 **"뭐가 바뀌었나?" 하고 찾아보게
만드는 거짓 신호**였다.

### 해결

`scripts/generate-version.mjs`가 빌드 전(`prebuild`)에 git에서
**각 시스템이 마지막으로 실제로 바뀐 커밋**을 뽑아 `src/generated/version.json`에
쓴다.

```
정산  v26.07.31.6 · 2026-07-31 02:12 배포
비교  v26.07.31.2 · 2026-07-31 01:34 배포
```

`v{YY}.{MM}.{DD}.{n}` — KST 날짜 + **그날 몇 번째 변경**인지. 하루에 여러 번 고치는
일이 흔해서 날짜만으로는 구분이 안 된다.

### 판별 기준 — 커밋 태그가 아니라 **경로**

커밋 메시지의 `[정산]`·`[비교]` 태그는 빠뜨릴 수 있지만 **바뀐 파일은 거짓말을
하지 않는다.**

| 구분 | 경로 |
|---|---|
| 정산 | `features/settlement`, `app/app`, `api/settlement` |
| 비교 | `app/calc-food`, `lib`, `api/{admin,analyze,audit-items,ocr-corrections,products,reference-search,session,sessions}` |
| **양쪽** | `middleware.ts`, `app/layout.tsx`, `app/(public)`, `app/login`, `app/auth`, `features/shared`, `lib/supabase`, `package.json`, `next.config` |

인증·미들웨어가 바뀌면 **양쪽 다 동작이 달라진다.** 한쪽에만 넣으면 다른 쪽
사용자가 "안 바뀌었다"는 잘못된 정보를 본다.

테스트(`__tests__`, `*.test.ts`)와 문서는 **제외**한다. 버전은 사용자가 보는 동작이
언제 바뀌었나를 알려주는 것이다 — 테스트를 고쳤다고 버전이 오르면 사용자는 달라진
걸 찾다가 시간을 버린다.

### git이 없는 환경

생성 결과를 `src/generated/version.json`에 **커밋해 둔다.** 빌드 환경에 git이 없으면
스크립트가 기존 파일을 그대로 두므로 화면이 비지 않는다.
