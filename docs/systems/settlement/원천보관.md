# 원천 파일 보관

> 정산 시스템 상세 — **필요할 때만 연다.** 개요·산식은 `../settlement.md`.
> ⚠️ 섹션 번호는 코드 주석(`docs §20` 등)이 참조하므로 **바꾸지 않는다.**

## 20. 원천 서버 보관 (2026-08-01 구현)

업로드한 원천을 서버에 두고, 그 달의 모든 작업이 그것을 쓴다.

### 왜 필요한가 — 말일 5시간

```
09:00  원천 도착 · 작업 시작
14:00  홈택스 업로드 완료          ← 5시간, 담당자 1명
```

이 다섯 시간 안에 **조정 요청이 몰려 들어온다**(본인부담·식당 이동). 원천이
브라우저 메모리에만 있으면 조정 한 건 넣을 때마다 파일이 살아 있어야 하고,
창을 닫는 순간 처음부터다. 다른 일을 하다 돌아올 수도 없다.

2026-07-31에는 7월 자료가 6월로 확정된 사고가 있었는데, **원본 파일이 없어**
마감 스냅샷(rev1)으로 되돌려야 했다. 원천이 남아 있었으면 바로 다시 돌렸다.

⚠️ **5시간은 법정 기한이 아니다.** 월합계 세금계산서는 공급시기가 속한 달의
다음 달 10일까지 발급하면 된다(국세청). 관행상의 목표이므로, "무조건 5시간"보다
**틀렸을 때 되돌릴 수 있게** 만드는 쪽이 우선이다.

### 파싱 결과는 저장하지 않는다 (실측 근거)

```
엑셀 읽기   59~82ms
파싱         1~2ms
```

파싱이 이 정도면 연 3만 행짜리 테이블과 그 동기화 문제를 떠안을 이유가 없다.
**파일만 두고 쓸 때마다 다시 판다.** 조회 화면이 필요해지면 그때 행 테이블을 얹는다.

### 구조

```
Storage  settlement-sources/<정산월>/<타임스탬프>_<종류들>.xlsx   비공개, 5년 보존
DB       settlement_source_files                                 메타 + 활성 표시
```

- **파일 1개가 2종을 담을 수 있다** (통합 파일 = 신세계 + CJ 집계표).
  그때는 행을 2개 만들고 `storage_path`를 공유한다. 종류별로 따로 갈아끼울 수
  있어야 하기 때문이다 — CJ 거래명세서만 재발행되는 일이 잦다.
- 되살릴 때는 **같은 경로를 한 번만 내려받는다.** 두 번 받으면 시간만 두 배다.
- 경로에 원본 파일명을 쓰지 않는다 — 한글·공백·괄호가 섞여 있다.
  어떤 파일이었는지는 `file_name` 컬럼에 그대로 남는다.

### 종류별 활성본은 하나뿐

`(period, kind) WHERE is_active` 부분 유니크 인덱스로 **DB에서 막는다.**
둘이 되면 어느 걸 쓸지 코드가 정해야 하는데, 그런 판단은 사람이 해야 한다.

**이전 것은 지우지 않고 `is_active`만 내린다.** 어제 같은 사고를 추적하려면
"그때 무엇을 올렸는지"가 남아야 한다. 마감 리비전과 같은 원칙이다.

### 기간이 어긋나면 저장하지 않는다

업로드 문턱에서 §8-4 검증을 건다. 잘못된 원천이 서버에 자리 잡으면 그 뒤
모든 작업이 오염된다. 화면은 409를 받아 "정산월을 바꾸고 다시" 버튼을 띄운다.

### 어떻게 쓰이나 (`service/resolve-sources.ts`)

```
요청에 파일이 있으면      → 그 파일을 쓴다
없고 보관본이 있으면      → 보관본을 쓴다
둘 다 없으면             → 막는다
```

**파일이 우선인 이유**: 보관 기능이 막히는 일이 생겨도 업무가 멈추면 안 된다.
5시간짜리 마감에서 도구가 통째로 안 되는 상황은 만들지 않는다.

화면의 `분석` 버튼은 파일이 있으면 **먼저 보관하고** 그다음 분석한다.
보관에 성공하면 브라우저에서 파일을 비운다 — 들고 있을 이유가 없다.
보관이 실패해도 분석은 진행하고 경고만 남긴다.

적용 라우트: `analyze` · `closing` · `report` · `invoice` · `venue-statement`.

⚠️ `report`는 `period`가 `26년7월` 같은 **표지 라벨**이라 보관본 조회용
`sourcePeriod`(YYYY-MM)를 따로 받는다.

```

되살리기    2.3초  (다운로드 — 2종이 같은 파일이라 1번만)
정산        1.3초
결과        단가 합계 102,359,832 — 6월 기록과 원단위 일치, 오류 0건
```

### 보관본이 있으면 업로드 상자를 접는다 (2026-08-01)

초록 카드로 "보관돼 있습니다"라고 써 놓고 그 아래에 큼직한 점선 업로드 상자를
그대로 두면, **또 올려야 하는 것처럼 보인다.** 실제로 그 지적을 받았다.

- 보관본이 있으면 상자를 접고 「다른 파일로 교체하기」만 남긴다
- 화면에 파일을 끌어다 놓으면 바로 다시 펼쳐진다 (드래그 경로는 그대로)
- 보관에 성공하면 다시 접고, 정산월을 바꾸면 교체 모드가 풀린다

⚠️ **보관본이 없는 달은 그대로 펼쳐 둔다.** 접을 이유가 없다. 기본 정산월은
지난달이라, 그달을 아직 안 올렸으면 카드가 없는 게 정상이다.

### 남은 것

- **원천 조회 화면** — 지금은 없다. 필요해지면 품목 행 테이블을 얹는다.
- 5년 경과분 정리 — 보존 기간이 지나면 지울 절차가 필요하다.
