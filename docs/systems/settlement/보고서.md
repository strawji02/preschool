## 13. 경영 보고서 ★ (2026-07-30 구현 완료)

`/app/settlement/report` — **마감된 달만** 보여준다. 업로드 화면의 미리보기와 달리
여기 숫자는 스냅샷에서 나오므로 담당자·수수료율이 바뀌어도 과거 보고서는 변하지 않는다.

구성: 헤드라인 3개(매출·총마진·영업이익) → 손익 워터폴 → 세금 3종 →
공급사별 → 영업자별(M·O·P·Q·R·V·원천세·U) → 유치원별 → 현금흐름(참고).

⚠️ **현금흐름은 발생 기준 추정값**임을 화면에 명시했다. 실제 입출금일은 §9 수금
관리가 들어와야 알 수 있다. 추정값을 확정값처럼 보여주면 통장과 대조할 때 혼란이 된다.

**실데이터 검증 (26년 6월)**: 헤드라인 10개 항목 전부 일치, 청구 대상 16곳 합계
102,346,907, 공급사별 매입 합계 74,009,016, 계산서 상호 스냅샷 고정 확인.

### 13-0. 설계 (원안)

#### 13-1. 설계 원칙

**세 가지 기준을 섞지 않고 나란히 놓는다.** 섞으면 "장부상 이익은 났는데 통장에
돈이 없다"를 설명할 수 없다.

| 기준 | 무엇을 답하는가 | 근거 |
|---|---|---|
| **발생(거래)** | 이번 달 얼마 팔고 얼마 사왔나 | 원천 업로드 = 확정값 |
| **세무(신고)** | 언제 얼마를 세무서에 내나 | 부가세·원천세·사업소득 |
| **현금(입출금)** | 통장에 실제로 얼마 남나 | 수금일·지급일 **수기 입력** |

**금액은 총액(세금 포함)이 기본, 공급가는 토글.** 산식의 M·P가 총액 기준이고
(§3), 수금·지급도 총액이라 총액이 업무 언어다. 공급가는 부가세 검산용으로만 쓴다.

#### 13-2. 화면 3단 (26년 6월 실값)

**① 매출·매입 — 거래 기준**

```
매출(유치원 청구)  102,346,907 = 면세 65,846,245 + 과세공급가 33,182,420 + 세액 3,318,242
매입(신세계·CJ)     74,009,016 = 공급가 … + 세액 2,413,235 + 면세 …
총마진 M            28,350,816
```
- 유치원 16곳 × 품목별 드릴다운, 공급사별(신세계/CJ) 매입 분해
- 마진율 표시: 매출 대비 27.7%
- ⚠️ 매출에서 **정산제외 사업장(본사)을 뺀다** — 계산서를 발행하지 않으므로

**② 영업 파트너 — 마진이 어떻게 쪼개지는가**

영업자별 워터폴 `M → −O → −P → −Q → R → −3.3% → U`

| | 합계 |
|---|---|
| 총마진 M | 28,350,816 |
| 적립금 O (플랫폼 5%) | 3,579,360 |
| 부가세차액 P | 905,912 |
| 사업자공제 Q | 2,320,500 |
| 영업자 세전 R | 21,542,074 |
| 원천세 (3.3%) | 531,960 |
| **영업자 실지급 U** | **21,010,114** |
| **본사 몫** | **6,808,742** |

본사 몫 = O + P + Q + 본사 자체 마진 2,970 → 항등식이 닫힌다.
**이게 회사의 실질 수익이다** — 매출총이익(M)이 아니라 이 숫자를 헤드라인으로 쓴다.

**③ 월 마감 재무 요약**

세금 3종을 각각 분리한다 (성격·납부시점이 다르다):

| 세금 | 계산 | 26년 6월 | 납부 |
|---|---|---|---|
| 부가가치세 | 매출세액 − 매입세액 | 3,318,242 − 2,413,235 = **905,007** | 분기 신고 |
| 원천세 | 소득세 + 지방세 | **531,960** | 익월 10일 |
| 사업소득 | 영업자 개인 신고 | 16,120,927 (신고액) | 지급명세서 제출 |

현금흐름:
```
유입  유치원 수금        102,346,907
유출  신세계·CJ 대금      74,009,016
      영업자 실지급       21,010,114
      원천세                 531,960
      부가세                 905,007
순현금                     5,890,810
```

⚠️ **부가세차액 회수액(905,912)과 실제 납부액(905,007)이 905원 다르다.**
본사 자체 매입세액 905원은 공제받지만 어느 영업자에게도 부담시키지 않아서다.
보고서에 대조 행으로 남겨 매달 확인한다 — 조용히 넘기면 누적된다.

#### 13-3. 발생 vs 현금 (§9 수금 관리와 연결)

- 미수금 = 청구합계 − 수금액 (유치원별 입금일자 수기 입력)
- 미지급 = 실지급액 − 지급완료액 (영업자별 지급일)
- **영업자 담당 유치원 전원 입금 완료 → 지급 요청 알림** (§9)
- 보고서 상단에 `발생 순이익 6,808,742 / 현금 순증 5,890,810` 를 나란히 놓고
  차이를 미수금·미지급으로 설명한다

#### 13-4. 확정 (2026-07-30, 사용자 확인)

**본사 사업장 12,925원 = 마케팅비.** 원가 9,955원이 마케팅 비용이고,
단가 12,925 / 차액 2,970은 **손익에 넣지 않는다** — 내부 대체 금액이고 계산서도 없다.

이렇게 처리하면 항등식이 정확히 닫힌다 (유령 마진과 905원 차이가 동시에 해소된다):

```
매출              102,346,907   ← 계산서 발행분 (본사 제외)
매출원가           73,999,061   ← 전체 매입 74,009,016 − 본사 9,955
총마진 M           28,347,846   = 영업자 4명 차액 합계와 원단위 일치
− 영업자 세전 R    21,542,074
= 본사 몫           6,805,772   = 적립금 3,579,360 + 부가세차액 905,912 + 공제 2,320,500
− 마케팅비              9,955
= 영업이익          6,795,817
```

**부가세 905원 차이는 이상 항목이 아니었다.** 회수액 P 905,912 − 납부액 905,007 = 905원은
**본사 마케팅비에 딸린 매입세액 공제분**이다. 보고서에는 대조 행으로 남기되 경고가 아니다.

**계산서는 현행 유지** — 품목마다 1장(16곳 → 88장). 품목1~4 슬롯은 쓰지 않는다.

**품목명은 화면에서 지정한다** — 신규 식당이 생기면 품목명을 입력해야 하고,
미지정이면 마감을 차단한다. §14 참고.
