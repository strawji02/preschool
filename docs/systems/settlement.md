# 급식 정산 시스템 (`[정산]`)

> 신규 개발. 매월 최소 1회 정기 사용 → 지속적 DB 관리 + 월 마감.
> 근거 문서: `유치원급식_정산시스템 요구사항 정의서(SRS).docx`
> 근거 데이터: `정산시스템_개발용_급식_정산_종합_26년_6월분.xlsx` (실제 26년 6월 정산)

## 1. 목적

신세계·CJ에서 매월 받는 원천 데이터를 업로드해 **유치원 매출 청구**와 **영업자 정산**을 자동화한다.
현재 담당자가 엑셀에서 수작업(셀 병합·수기 열 추가)으로 하는 과정을 전부 시스템화한다.

## 2. 프로세스

```
원천 업로드(신세계·CJ) → 파싱·정규화 → 영업자-유치원 매핑
  → [매출] 과세/면세 분리 → 유치원 청구액
  → [정산] 마진 → 공제 → 3.3% → 영업자 지급액
  → 엑셀 3종 출력 (홈택스 / 영업자 / 세무사)
```

## 3. 정산 산식 ★ (실제 엑셀 수식에서 추출, 역검증 완료)

집계 단위: **영업자 → 유치원(사업장)×식당**. 아래는 영업자별 합계 기준.

```
차액(총마진)  M = Σ(단가합계 − 원가합계)                    ← 총액(세액 포함) 기준
적립금(플랫폼) O = ROUNDUP((원가합계 − 원가세액) × 5%, -1)    ← 10원 올림
부가세차액     P = 단가세액 − 원가세액                       ← 영업자 전액 부담
사업자공제     Q = 매월 수기 입력 (커피차 등 부가서비스 비용)
지급액(세전)   R = M − O − P − Q

신고액         V = 영업자 유형에 따라 분기 ★
                 · 코파운더  → R + O   (적립금을 사업소득 신고액에 포함)
                 · 일반 파트너 → R      (신규 등록 파트너는 전부 일반)
소득세         S = ROUNDDOWN(V × 3%, -1)     ← 신고액(V) 기준, 10원 내림
지방소득세     T = ROUNDDOWN(S × 10%, -1)    ← 10원 내림
실지급         U = R − S − T                 ← 세전(R)에서 차감
```

- 총액차액 − 부가세차액 = 공급가 기준 차액 → SRS의 "공급가 기준 총마진"과 **수학적으로 동일**.
- 코파운더 3명: **김중영·이동현·조성곤**. 그 외 및 신규 등록자는 일반.
- 김중영은 과거 엑셀에서 원천징수 누락 → **시스템에서는 동일하게 원천징수 적용**.

## 4. 분할 신고

한 영업자의 사업소득을 **여러 명 명의로 나눠 신고**하는 운영을 지원한다.
- 배분은 **수기 입력**(성명 + 금액).
- **검증 필수**: 분할 합계 == 해당 영업자 신고액(V). 불일치 시 마감 차단.
- 실제 사례(26년 6월): 이동현 13,490,317 → 이동현 4,490,317 + 김인순 5,000,000 + 이유나 4,000,000.

## 5. 원천 데이터 구조

**신세계** (`신세계_전체 일반`, 536행) — 품목 단위, **2행 병합 헤더**
```
순번 | 사업장(코드,명) | 식당(코드,명) | 입고일자 | 카테고리 | 품목코드 | 품목명 | 규격 | 단위 | 면과세 | 수량
     | 납품(단가,금액,세액,총액)   ← 원가(매입)
     | 가맹점(단가,금액,세액,총금액) ← 유치원 청구(매출)
```

**CJ** (`CJ_전체 집계표`, 40행) — 사업장×식당 집계 단위, 1행 헤더
```
번호 | 사업장코드 | 사업장 | 식당코드 | 식당명 | 사업부 | 팀
   | 원가: 과세공급가, 과세부가세, 과세금액, 면세, 합계(a)
   | 단가: 과세공급가, 과세부가세, 과세금액, 면세, 합계(b)
   | 차액(b−a)
```

⚠️ **레벨이 다름** — 신세계는 품목, CJ는 집계. 공통 정규화 지점은 **사업장×식당×과세구분**.
신세계 품목 데이터는 이 레벨로 집계해서 CJ와 합산한다.

### 6-1. 홈택스 일괄발행 양식 ★ (2026-07-30 실측·역검증 완료)

근거 파일: `(세금)계산서 발행을 위한 엑셀 파일_26년 6월.xlsx`(과세),
`계산서 발행을 위한 엑셀 파일_26년 6월.xlsx`(면세) — 실제 홈택스에 올린 파일.

**공통 구조**: 1~5행 비움, **6행 헤더, 7행부터 데이터.** 시트명 `Sheet1`.
**1행 = 계산서 1장 = 품목 1건.** 품목2~4 슬롯은 쓰지 않았다.

| | 과세(세금계산서) | 면세(계산서) |
|---|---|---|
| 열 수 | 59 (BG) | 54 (BB) |
| 종류(A) | `01` 일반 | `05` 일반 |
| 공급가액합계 | T | T |
| **세액합계** | **U** | 없음 |
| 비고 | V | U |
| 품목1 블록 | W~AD (8열) | V~AB (7열) |
| 영수/청구 | BG = `02`(청구) | BB = `02`(청구) |

⚠️ **세액 열(U) 때문에 과세 파일은 U 이후 모든 열이 1칸 밀린다.** 두 양식을 같은
코드로 만들 때 오프셋을 상수로 두지 말고 양식별 열 맵을 따로 정의할 것.

- 작성일자(B) `20260630` — 월말일, 8자리 문자열
- 일자1(W/V) `30` — **2자리, 작성년월 제외**
- 공급자는 항상 본사 고정: `8310503575` / 키즈웰에듀푸드 / 김중영 / 도매 및 소매업 / 교재
- 공급받는자 업태·종목은 16곳 모두 `유치원` / `유치원`, 이메일2는 전부 미사용
- ⚠️ 원본에는 **영수/청구 열만 채워진 빈껍데기 행이 42개**(면세 20, 과세 22) 있다.
  생성기는 만들지 않는다.

**역검증 (26년 6월, 4개 항목 전부 원단위 일치)**

| 항목 | 집계표_정산용 | 홈택스 파일 |
|---|---|---|
| 과세 공급가 | 33,182,420 | 33,182,420 |
| 과세 세액 | 3,318,242 | 3,318,242 |
| 면세 금액 | 65,846,245 | 65,846,245 |
| 총 청구액 | 102,346,907 | 102,346,907 |

- 유치원 16곳 / 과세 47장 + 면세 41장 = 88장
- ⚠️ **본사(정산제외) 12,925원은 계산서 대상이 아니다.** 자기 자신에게 발행하지 않는다.
  단가합계 102,359,832 − 본사 12,925 = 102,346,907. 매출 산출은 **정산제외 사업장을 뺀다.**
- ⚠️ **`복자유치원`이라는 상호가 3곳**(사업자번호 1318208466 / 5798200308 / 3058221435)
  + `수원복자유치원` 별도. **상호는 키가 아니다. 사업자등록번호가 키다.**

**품목명은 식당명에서 기계적으로 나오지 않는다 → 마스터에 저장해야 한다**

식당명 51건 중 15건은 품목 문자열을 포함하지 않고, 포함해도 표기가 다르다:

| 식당명 | 실제 품목 |
|---|---|
| `키즈웰에듀푸드(선경유치원)` (접미사 없음) | `급식재료` |
| `키즈웰에듀푸드(젬마유치원_수익자)` | `급식재료(수익자)` |
| `키즈웰에듀푸드(부산_복자유치원_식재료(교원))` | `급식재료(교직원)` |
| `국제유치원(키즈웰) 행사` | `행사용` |
| `키즈웰에듀푸드(복자유치원_방과후간식재료)` | `방과후간식` |

⚠️ **N개 식당 → 1장으로 합산되는 경우가 있다.** 해밀유치원 과세:
`(해밀유치원)` 39,490 + `(해밀유치원_급식재료)` 96,650 = **급식재료 136,140** 1장
(세액도 3,949 + 9,665 = 13,614로 정확히 합산). 따라서 발행 단위는 식당이 아니라
**(유치원 사업자번호 × 품목 × 과세구분)** 이다.

금액 기준으로 식당→품목을 역추적하면 **89건 중 87건이 유일 매칭**되고, 남은 2건이
위 해밀 합산 사례다. 이 결과를 시드로 쓰되 사람이 한 번 검토한다.

## 7. 개인정보 방침

- **주민번호는 저장하지 않는다.** 지급명세서에 빈칸으로 출력 → 사용자가 다운로드 후 별도 처리.
- 저장 대상: 세금계산서 발행용 **상호, 주소, 대표자, 이메일, 사업자등록번호**만.
- 계좌정보 저장 여부는 미결 — 필요해지면 별도 결정.

## 8. 월 마감

상태: `작성중 → 확정 → 마감`
- **마감 후에도 수정 가능**(권한 있는 사용자). 수정 시 이력 남길 것.
- 마감 전 검증: 분할 신고 합계 일치, 매핑 누락 없음.

## 9. 수금 관리

- 유치원별 **입금일자만 사용자 수기 입력**.
- 한 영업자가 담당하는 **모든 유치원 입금이 완료되면** → 해당 영업자 지급 요청 **알림**.
- 미수금(잔액) = 청구합계 − 수금액.

## 10. 마스터 데이터

- `영업자`: 이름, **유형(코파운더/일반)**, **개인/사업자 구분**, 기본 수수료율(5%, 개별 설정 가능), 연락처
  - 수수료율 **월별 이력** 관리 여부는 미결
- `유치원(사업장)`: 사업장코드, 상호, 사업자등록번호, 대표자, 주소, 이메일, **담당 영업자 ID**
- 매핑 키: 원천 데이터의 **사업장 코드**

### 확정된 것 (2026-07-29)

**세전 정산액이 음수일 때 → 0 처리 + 경고.**
받을 게 없는 달이므로 신고할 사업소득도 없다고 본다. 코파운더라도 적립금을 신고액에
넣지 않는다(0 처리가 우선). 원래 음수값은 `preTaxRaw`에 보존하므로, 이월 정책이
정해지면 거기서 이어가면 된다. 조용히 0으로 만들지 않고 반드시 경고를 남긴다.

**정산 대상이 아닌 사업장(본사 등) → 명시적 `정산제외` 표시.**
매핑 누락과 반드시 구분한다 — 섞이면 "마감 전 매핑 누락 없음" 검증이 무의미해진다.
`settlement_venues.is_excluded`로 표시하고, 매핑값은 세 상태를 갖는다:
`영업자 id` = 집계 / `null` = 의도적 제외(경고 없음) / 키 없음 = 미배정(경고·마감 차단).

### `사업소득 신고내역` 시트의 다른 정의 두 개 (2026-07-30 실측)

지급명세서는 `집계표_정산용`과 **열 이름이 같아도 값이 다르다.** 두 문서를 나란히
놓고 대조할 때 반드시 알고 있어야 한다.

1. **세액을 명의별로 계산한다.** 영업자 전체 신고액(V)이 아니라 분할된 각 명의의
   금액에 3%/10%를 적용한다 — 실제로 각 사람 앞으로 원천징수되기 때문이다.
   10원 내림을 명의별로 하므로 **합계가 전체 기준과 어긋날 수 있다**(경고로 알린다).
   26년 6월 이동현은 우연히 일치했다 (명의별 합 445,170 = 전체 기준 445,170).
2. **이 시트의 `실지급액` = 사업소득액 − 소득세계.** 집계표의 실지급(U)은
   `세전(R) − 소득세 − 지방세`라서 값이 다르다. 조성곤 예: 신고내역 1,173,955 vs
   집계표 971,215. 신고 문서이므로 신고액에서 세금만 뺀 금액을 적는다.

대조 결과: 원본 5개 행(김인순·이유나·이동현·조성곤·김영수) + 계 행 전 항목 일치.
**김중영은 원본 신고내역에 없다** — 집계표에서 원천징수가 누락된 것과 같은 원인이다.
확정 규칙대로 채우면 8,715,637원(소득세계 287,600 / 실지급 8,428,037)이 된다.

## 13. 경영 보고서 (설계 — 2026-07-30)

### 13-1. 설계 원칙

**세 가지 기준을 섞지 않고 나란히 놓는다.** 섞으면 "장부상 이익은 났는데 통장에
돈이 없다"를 설명할 수 없다.

| 기준 | 무엇을 답하는가 | 근거 |
|---|---|---|
| **발생(거래)** | 이번 달 얼마 팔고 얼마 사왔나 | 원천 업로드 = 확정값 |
| **세무(신고)** | 언제 얼마를 세무서에 내나 | 부가세·원천세·사업소득 |
| **현금(입출금)** | 통장에 실제로 얼마 남나 | 수금일·지급일 **수기 입력** |

**금액은 총액(세금 포함)이 기본, 공급가는 토글.** 산식의 M·P가 총액 기준이고
(§3), 수금·지급도 총액이라 총액이 업무 언어다. 공급가는 부가세 검산용으로만 쓴다.

### 13-2. 화면 3단 (26년 6월 실값)

**① 매출·매입 — 거래 기준**

```
매출(유치원 청구)  102,346,907 = 면세 65,846,245 + 과세공급가 33,182,420 + 세액 3,318,242
```

- ⚠️ 매출에서 **정산제외 사업장(본사)을 뺀다** — 계산서를 발행하지 않으므로

**② 영업 파트너 — 마진이 어떻게 쪼개지는가**

영업자별 워터폴 `M → −O → −P → −Q → R → −3.3% → U`

| | 합계 |
|---|---|
| 총마진 M | 28,350,816 |
| 적립금 O (플랫폼 5%) | 3,579,360 |

| 사업자공제 Q | 2,320,500 |

**이게 회사의 실질 수익이다** — 매출총이익(M)이 아니라 이 숫자를 헤드라인으로 쓴다.

### 13-3. 발생 vs 현금 (§9 수금 관리와 연결)

- 미수금 = 청구합계 − 수금액 (유치원별 입금일자 수기 입력)
- 미지급 = 실지급액 − 지급완료액 (영업자별 지급일)
- **영업자 담당 유치원 전원 입금 완료 → 지급 요청 알림** (§9)
- 보고서 상단에 `발생 순이익 6,808,742 / 현금 순증 5,890,810` 를 나란히 놓고
  차이를 미수금·미지급으로 설명한다

### 13-4. 미결 — 사용자 확인 필요

1. **본사 사업장 12,925원의 성격.** 원가 9,955 / 단가 12,925 / 차액 2,970인데
   계산서를 발행하지 않는다. 본사 임직원 급식(내부 비용)인가, 미발행 매출인가?
   손익 계산에서 매출로 볼지 비용으로 볼지가 여기서 갈린다.
2. **계산서를 유치원당 1장으로 묶을지.** 현재는 품목마다 1장(16곳 → 88장).
   품목1~4 슬롯을 쓰면 장수를 줄일 수 있다. 현행 유지가 기본.
3. **품목명 마스터를 화면에서 편집할지.** 신규 식당이 생기면 품목명을 지정해야
   계산서를 만들 수 있다 (미지정 시 마감 차단).
