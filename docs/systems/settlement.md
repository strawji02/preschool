# 급식 정산 시스템 (`[정산]`)

> 신규 개발. 매월 최소 1회 정기 사용 → 지속적 DB 관리 + 월 마감.
> 근거 문서: `유치원급식_정산시스템 요구사항 정의서(SRS).docx`
> 근거 데이터: `정산시스템_개발용_급식_정산_종합_26년_6월분.xlsx` (실제 26년 6월 정산)

## 1. 목적

신세계·CJ에서 매월 받는 원천 데이터를 업로드해 **유치원 매출 청구**와 **영업자 정산**을 자동화한다.
현재 담당자가 엑셀에서 수작업(셀 병합·수기 열 추가)으로 하는 과정을 전부 시스템화한다.

## 2. 프로세스

```
원천 업로드(신세계·CJ) → 파싱·정규화 → 영업자-유치원 매핑
  → [매출] 과세/면세 분리 → 유치원 청구액
  → [정산] 마진 → 공제 → 3.3% → 영업자 지급액
  → 엑셀 3종 출력 (홈택스 / 영업자 / 세무사)
```

## 3. 정산 산식 ★ (실제 엑셀 수식에서 추출, 역검증 완료)

집계 단위: **영업자 → 유치원(사업장)×식당**. 아래는 영업자별 합계 기준.

```
차액(총마진)  M = Σ(단가합계 − 원가합계)                    ← 총액(세액 포함) 기준
적립금(플랫폼) O = ROUNDUP((원가합계 − 원가세액) × 5%, -1)    ← 10원 올림
부가세차액     P = 단가세액 − 원가세액                       ← 영업자 전액 부담
사업자공제     Q = 매월 수기 입력 (커피차 등 부가서비스 비용)
지급액(세전)   R = M − O − P − Q

신고액         V = 영업자 유형에 따라 분기 ★
                 · 코파운더  → R + O   (적립금을 사업소득 신고액에 포함)
                 · 일반 파트너 → R      (신규 등록 파트너는 전부 일반)
소득세         S = ROUNDDOWN(V × 3%, -1)     ← 신고액(V) 기준, 10원 내림
지방소득세     T = ROUNDDOWN(S × 10%, -1)    ← 10원 내림
실지급         U = R − S − T                 ← 세전(R)에서 차감
```

- 총액차액 − 부가세차액 = 공급가 기준 차액 → SRS의 "공급가 기준 총마진"과 **수학적으로 동일**.
- 코파운더 3명: **김중영·이동현·조성곤**. 그 외 및 신규 등록자는 일반.
- 김중영은 과거 엑셀에서 원천징수 누락 → **시스템에서는 동일하게 원천징수 적용**.

## 4. 분할 신고

한 영업자의 사업소득을 **여러 명 명의로 나눠 신고**하는 운영을 지원한다.
- 배분은 **수기 입력**(성명 + 금액).
- **검증 필수**: 분할 합계 == 해당 영업자 신고액(V). 불일치 시 마감 차단.
- 실제 사례(26년 6월): 이동현 13,490,317 → 이동현 4,490,317 + 김인순 5,000,000 + 이유나 4,000,000.

## 5. 원천 데이터 구조

**신세계** (`신세계_전체 일반`, 536행) — 품목 단위, **2행 병합 헤더**
```
순번 | 사업장(코드,명) | 식당(코드,명) | 입고일자 | 카테고리 | 품목코드 | 품목명 | 규격 | 단위 | 면과세 | 수량
     | 납품(단가,금액,세액,총액)   ← 원가(매입)
     | 가맹점(단가,금액,세액,총금액) ← 유치원 청구(매출)
```

**CJ** (`CJ_전체 집계표`, 40행) — 사업장×식당 집계 단위, 1행 헤더
```
번호 | 사업장코드 | 사업장 | 식당코드 | 식당명 | 사업부 | 팀
   | 원가: 과세공급가, 과세부가세, 과세금액, 면세, 합계(a)
   | 단가: 과세공급가, 과세부가세, 과세금액, 면세, 합계(b)
   | 차액(b−a)
```

⚠️ **레벨이 다름** — 신세계는 품목, CJ는 집계. 공통 정규화 지점은 **사업장×식당×과세구분**.
신세계 품목 데이터는 이 레벨로 집계해서 CJ와 합산한다.

## 6. 산출물 (엑셀 3종)

1. **매출 세금계산서/계산서 일괄발행** — 홈택스 업로드용. 과세→세금계산서, 면세→계산서로 분리.
   *양식 파일 미수령 — 개발 중 제공 예정*
2. **영업자별 개별 정산 내역서** — 유치원별 매출·원가, 공제 상세, 3.3%, 실지급액
3. **사업소득 지급명세서** — 세무사 제출용. **주민번호 칸은 빈칸으로 출력**하고 사용자가 직접 채운다.

## 7. 개인정보 방침

- **주민번호는 저장하지 않는다.** 지급명세서에 빈칸으로 출력 → 사용자가 다운로드 후 별도 처리.
- 저장 대상: 세금계산서 발행용 **상호, 주소, 대표자, 이메일, 사업자등록번호**만.
- 계좌정보 저장 여부는 미결 — 필요해지면 별도 결정.

## 8. 월 마감

상태: `작성중 → 확정 → 마감`
- **마감 후에도 수정 가능**(권한 있는 사용자). 수정 시 이력 남길 것.
- 마감 전 검증: 분할 신고 합계 일치, 매핑 누락 없음.

## 9. 수금 관리

- 유치원별 **입금일자만 사용자 수기 입력**.
- 한 영업자가 담당하는 **모든 유치원 입금이 완료되면** → 해당 영업자 지급 요청 **알림**.
- 미수금(잔액) = 청구합계 − 수금액.

## 10. 마스터 데이터

- `영업자`: 이름, **유형(코파운더/일반)**, **개인/사업자 구분**, 기본 수수료율(5%, 개별 설정 가능), 연락처
  - 수수료율 **월별 이력** 관리 여부는 미결
- `유치원(사업장)`: 사업장코드, 상호, 사업자등록번호, 대표자, 주소, 이메일, **담당 영업자 ID**
- 매핑 키: 원천 데이터의 **사업장 코드**

## 11. 미결 사항

- 홈택스 일괄발행 엑셀 양식 (개발 중 제공 예정)
- 수수료율 월별 이력 관리 필요 여부
- 계좌정보 저장 여부
- 기존 "영업자 손익 보고서"(제안 단계, `src/lib/partner-profit.ts`)에 **사업자공제·부가세차액·3.3%** 를 반영해
  실제 정산과 일치시킬지 — 현재는 반영 안 되어 예상액이 실제보다 높게 나옴

### 확정된 것 (2026-07-29)

**세전 정산액이 음수일 때 → 0 처리 + 경고.**
받을 게 없는 달이므로 신고할 사업소득도 없다고 본다. 코파운더라도 적립금을 신고액에
넣지 않는다(0 처리가 우선). 원래 음수값은 `preTaxRaw`에 보존하므로, 이월 정책이
정해지면 거기서 이어가면 된다. 조용히 0으로 만들지 않고 반드시 경고를 남긴다.

**정산 대상이 아닌 사업장(본사 등) → 명시적 `정산제외` 표시.**
매핑 누락과 반드시 구분한다 — 섞이면 "마감 전 매핑 누락 없음" 검증이 무의미해진다.
`settlement_venues.is_excluded`로 표시하고, 매핑값은 세 상태를 갖는다:
`영업자 id` = 집계 / `null` = 의도적 제외(경고 없음) / 키 없음 = 미배정(경고·마감 차단).
