# 급식 거래명세서 비교 시스템 (`[비교]`)

> **운영 중 · 95% 완성.** 비정기 사용. 신규 기능보다 **안정성이 최우선**.
> 정산 시스템 개발이 이 시스템을 깨뜨리면 안 됩니다.

## 1. 목적

유치원이 현재 쓰는 급식업체 거래명세서를 업로드해, **신세계푸드 단가와 비교**하여
절감액을 산출하고 원장 제출용 제안서·영업자 손익 보고서를 만든다.

**비교 대상 공급사는 신세계 1곳뿐**이다. (CJ는 정산 시스템에서만 등장)

## 2. 위치와 접근 권한

- 화면: `src/app/calc-food/` — **경로 이동 계획 없음.** 운영 중이라 URL을 바꾸면
  북마크가 깨진다. `/app/*` 아래로 옮기는 건 실익이 없다.
- 도메인 로직: `src/lib/` (spec-parser, unit-conversion, matching-kpi, partner-profit,
  `funnel/`)

### 접근 조건 — 두 개를 모두 넘어야 한다 (2026-07-31, migration 056)

| 층 | 무엇 | 어디 |
|---|---|---|
| 1 | 로그인 (화이트리스트) | `middleware.ts` → `/calc-food` |
| 2 | `can_access_comparison = true` | `calc-food/layout.tsx` → `requireComparisonAccess()` |

**2026-07-30까지 이 화면은 로그인 없이 열려 있었다.** 거래처 단가가 담긴 원천
데이터를 다루므로, 화이트리스트 안에서도 지정한 사람만 보도록 좁혔다.

`role = 'admin'`은 **정산 마감 해제 권한**을 뜻하며 비교 시스템 접근과는 별개

뿐이다. URL을 직접 쳐도 위 2층에서 막힌다. (`comparison-reveal.tsx`, `clicks >= 3`)

### 배포 버전 표시 (2026-07-31)

화면 제목 옆에 `COMPARISON_VERSION`이 뜬다. **비교 시스템이 실제로 바뀐 커밋**의
날짜·시각이며, 정산만 고친 배포에서는 값이 그대로 남는다.
판별 경로는 `scripts/generate-version.mjs`가 정본이다 (settlement.md §16).

## 3. 워크플로

```
업로드(Excel/PDF/이미지) → 파싱 → 신세계 상품 매칭(AI 추천 + 직접 검색)
  → 검수자 확정 → 리포트(절감액) → 제안서 PDF/PPT + 영업자 손익 PPT + 엑셀
```

## 4. 핵심 규칙 (건드릴 때 주의)

- **확정은 매칭이 있어야만 가능** (`src/lib/confirm-guard.ts`). 무매칭 Enter = 확정 없이 다음으로.
  세션 로드 시 과거 오염 데이터 자가치유.
- **공급율(supplyRate)** 은 매칭 화면과 보고서가 **공유**한다 (`useSupplyRate` 훅,
  `proposal_extras.supply_rate`, 기본 1.25). 양쪽 절감액이 같은 값이어야 한다.
- **per-item 반올림**: 모든 합계는 `Σ Math.round(item)`. 카테고리 카드 합 == 헤드라인 절감액.
  순손실 카테고리도 **음수 그대로 표시**(clamp 금지).
- **단위중량 파싱**(`spec-parser.ts` + `invoice-unit-weight.ts`): 명세서마다 양식이 다르다.
  - 규격 선두 `[냉동]`·`[실온]` 등 **보관조건 태그 제거 후** 발주단위 판별
  - 규격이 KG/PK/BOX를 담으면 **규격 우선**(coarse한 `extracted_unit`이 덮어쓰지 못하게)
  - `Xg*Nea`는 곱함, 단 `.../BOX`(박스 묶음수)면 곱하지 않음
  - 개당 무게 범위는 **평균** 사용
- **품목군별 허용 오차**(`funnel/price-cluster.ts`): 농산물 ±40% / 축산물 ±25% /
  가공품 ±20% / 기타 ±30%. 농산물은 계절 변동이 커서 넓고, 가공품이 ±40% 차이나면
  다른 물건이다. 규격을 못 읽어도 **후보에서 버리지 않고** 순위만 뒤로 민다 —
  버리면 검수자가 손으로도 못 고른다.

## 9. 신세계 단가 기준월 (2026-08-14 합의, 미착수)

세션을 시작할 때 **몇 월 신세계 단가로 비교할지** 고른다. 매칭·절감액이 그 달
단가를 쓴다.

### 먼저 알아야 할 사실 — `products`가 3개월 낡았다

`products`(비교 시스템의 신세계 DB)와 정산이 받은 월별 단가표는 **같은 데이터**다.
`standard_price` = 단가표 `결정단가`, `origin`·`order_deadline`·`supplier_partner`도 대응한다.

```
products 24,593행   SHINSEGAE 8,787(활성 7,964) · CJ 15,806
last_synced_at 5/9 이후 갱신  0건
```

8월 단가표와 대조한 결과:

```
코드 겹침 7,508 · products에 없는 신규 품목 320
단가 같음 6,273 · 다름 1,235   ← 16.4%가 틀렸다
  올랐는데 반영 안 됨 943 / 내렸는데 반영 안 됨 292
  평균 차이 17.5% · 최대 560%
```

⚠️ **틀린 것의 76%가 "실제로는 올랐는데 낡은 낮은 단가"** 다. 낮은 단가로 비교하니
**절감액이 과대 계상**된다 — 제안서에 부풀려진 숫자가 나갔을 수 있다.

### 설계 — 임베딩은 달마다 복제하지 않는다

`products`에 `period`를 붙여 월별로 만들면 8,000행 × 12개월 + 임베딩 96,000개가 된다.
**임베딩·search_vector는 품목명에서 나오고 품목명은 달마다 안 바뀐다.** 가격만 바뀐다.

```
products              품목이 존재하는가 + 어떻게 찾는가   (달과 무관)
                      embedding · search_vector · ppu · 규격파싱
shinsegae_price_book  그 달에 얼마인가 + 원산지          (월별 이력, migration 061)
```

### 바꿀 지점은 API 5곳뿐

`standard_price`가 UI 12개 파일에서 읽히지만, UI는 **API가 준 상품 객체를 그대로
쓴다.** API 경계에서 단가만 그 달 값으로 덮으면 UI는 한 줄도 안 고친다.

```
/api/products/search      매칭 후보 검색
/api/products/[id]
/api/products/last-sync
/api/sessions/[id]        세션 로드 시 확정 매칭
src/lib/matching.ts       AI 추천
```

### 세션에 기준월을 굳힌다

`audit_sessions.price_book_period` (nullable) 한 칼럼.

```
NULL      → 지금까지처럼 products.standard_price   (기존 세션 18개)
'2026-08' → 그 달 price_book 단가
```

⚠️ **기존 세션은 그대로 둔다** (2026-08-14 결정). 이미 제출한 제안서의 숫자가
나중에 바뀌면 안 된다 — 정산의 마감 스냅샷과 같은 원리다.

⚠️ **매칭을 시작한 뒤에는 기준월을 못 바꾼다.** 중간에 바꾸면 확정한 항목과 새 항목이
다른 달 단가를 쓴다. 바꿔야 하면 새 세션을 만든다.

### 그 달에 없는 품목은 후보에서 버리지 않는다

§4 원칙 그대로다 — 버리면 검수자가 손으로도 못 고른다. 대신 `8월 단가표에 없음`
배지를 붙여 검수자가 판단하게 한다. 억지로 다른 달 단가를 끌어오면 **조용히 틀린
절감액**이 나온다.

### 작업 순서

```
1. 단가표 코드를 features/shared/price-book으로 이동
   (CLAUDE.md — settlement ↔ comparison 직접 import 금지)
2. migration 062: audit_sessions.price_book_period + products 신규 320개 upsert
3. API 5곳 단가 치환 (NULL이면 기존 동작 그대로)
4. 화면: 업로드 **앞에** 기준월 선택 + 세션 목록·리포트에 표시
5. 검증: 기존 세션 18개 절감액이 한 원도 안 바뀌는지 대조
```

⚠️ **임베딩은 기존과 같은 모델이어야 한다.** 다른 모델로 만들면 그 320개는 벡터
공간이 어긋나 검색에서 엉뚱하게 뜬다. 착수 전에 기존 생성 코드의 모델명·차원을 확인한다.
